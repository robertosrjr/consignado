# Technical Documentation

## Scope

This skill helps you create structured technical documentation including:
- **ADRs (Architecture Decision Records)** - Document significant architectural decisions and their context
- **DDAs (Detailed Design Architecture)** - Detail technical implementation before coding
- **READMEs** - Comprehensive system documentation
- **Technical Manuals** - Operational and developer guides

## Workflow

1. Clarify the documentation type and audience (developers, architects, operators).
2. Use the appropriate template structure (ADR, DDA, README, or Manual).
3. Apply clear formatting with well-nested headers, code blocks, and Mermaid diagrams where helpful.
4. Focus on clarity and concision - each section should have a direct objective.
5. Ensure natural stopping points and structured output without intermediate noise.

## Rules

- Use clean Markdown with proper header nesting and language-specific code blocks.
- Include Mermaid diagrams to illustrate flows and architectures.
- Document trade-offs and consequences alongside decisions.
- Focus on the "why" not just the "what" in architectural decisions.
- Maintain alignment across the team with clear, concise language.
